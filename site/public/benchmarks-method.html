Hushpen benchmarks

How we test dictation apps, so you can check us

Suraj Mandal · 20 November 2026 · See the results

The short version

We put 10 speech to text setups through the same test on one Mac: Hushpen with 5 speech models, Handy 0.10.1, FluidVoice 1.6.13, MacWhisper 15.11, VoiceInk 2.27 and Buzz 1.4.5. Each one wrote out the same 36 clips from TED talks, spoken in 19 English accents. Then we checked every transcript word by word against the talk's human-made captions. Buzz got the most words right, 95.1 out of 100, and Hushpen with Whisper Turbo got 95.0. FluidVoice wrote out one minute of audio in 0.37 s, quicker than anyone else. Hushpen's default model, Hushpen N, got 94.5 words right and took 0.80 s. In the real Hushpen app it types while you talk, so the text was done 0.30 s after the speaker stopped (0.29-0.33 s, 3 runs). Hushpen K got 93.6, and it's the one to pick for long recordings: 30 minutes in 17.0 s, against 23.1 s for Hushpen N. Below you'll find the full method, how we kept it fair, what the test can't tell you, and how to run it yourself.

2How we kept it fair

  1. Same clips for every app. Every setup got the same 37 WAV files, 16 kHz mono, cut once by a script. No app saw a different copy.
  2. Default settings. No custom words, no prompt and no language hint beyond each app's default.
  3. Nothing tuned on the test clips. The clips were picked by fixed rules (about 1 minute into each talk, whole caption lines, no laughter or applause) before any app ran. No setting was changed after we saw a score.
  4. No best-of picks. Accuracy is one run per clip, scored as it came out.
  5. Warm model, load time left out. The model is loaded before the clock starts. Load time is measured on its own and not added to the speed numbers.
  6. Median of 3 runs. Each speed number is the middle of 3 runs on the same file, so one slow run does not change the result.
  7. One scoring path. Every transcript and every caption goes through the same text normalizer and the same word error rate code.

3How we score

It all comes down to one question: of the words the speaker said, how many did the app get right?

  1. Normalize both sides. The Whisper English text normalizer makes text lowercase, removes punctuation, writes numbers and spellings the same way, and removes fillers such as "um".
  2. Word error rate. jiwer counts the words that were swapped, dropped or added, over all clips together, and divides by the number of caption words.
  3. Words right. 100 minus the word error rate. 95 words right means about 5 mistakes in every 100 words.
  4. Speed. Seconds to write out one minute of audio, from a 1 minute file. The speed files are the clips joined into one recording, then cut to 5 s, 15 s, 30 s, 1 min, 2 min and 5 min, and looped to 10 and 30 min.

5What this test can't tell you

  • Paid apps were not tested. Superwhisper, Wispr Flow, Aqua Voice, Willow Voice and Spokenly have no numbers here.
  • The captions skip some words. TED captions leave out some "uh"s and repeated words, so every setup loses a few points for words the speaker really said.
  • One clip was not scored. On Evgeny Morozov's talk the captions run about 5 s ahead of the sound. That clip was written out but not scored.
  • Each app is timed at its own edge. Hushpen time is its transcribe call. FluidVoice time runs from sending the file to its local API to getting the text back. Handy time is the inference time its command line tool reports.
  • Only Hushpen was timed from when you stop talking. The other apps have no end to end time here. Their speed is the time to write out a file.
  • One machine. All Mac numbers come from one Apple M4 Pro with 24 GB. Other Macs will be faster or slower.
  • Hushpen N has two paths. When you dictate, its live text engine writes the text while you speak. A recording file runs through the transcribe call. Its words right and file speeds come from the transcribe call.

6Run it yourself

You need a Mac or PC, Python 3, ffmpeg and yt-dlp. The clip list is in the appendix below. The audio is not published, so you cut it yourself from the talks.

  1. Install the tools.pip install jiwer whisper-normalizer yt-dlp
  2. Download a talk and its human captions.yt-dlp -x --audio-format wav --write-subs --sub-langs en --sub-format vtt -o talk "<YouTube link>"
  3. Cut the clip at the times in the appendix, as 16 kHz mono.ffmpeg -ss <start> -to <end> -i talk.wav -ac 1 -ar 16000 -c:a pcm_s16le clip.wav
  4. Save the caption lines between the same times as the truth text.Name it after the clip, such as clip.truth.txt.
  5. Write out each clip with the app's default settings.In Hushpen, open Manual, drop the WAV files in, and export TXT next to each clip, such as clip.txt.
  6. Score all clips together with the script below.python3 score.py
# score.py: words right out of 100 over every clip in this folder
from pathlib import Path
import jiwer
from whisper_normalizer.english import EnglishTextNormalizer

n = EnglishTextNormalizer()
clips = sorted(p.stem for p in Path(".").glob("*.wav"))
truth = [n(Path(c + ".truth.txt").read_text()) for c in clips]
heard = [n(Path(c + ".txt").read_text()) for c in clips]
print(round(100 - 100 * jiwer.wer(truth, heard), 1))

For speed, open the app and load the model first. Then time one file 3 times and keep the middle time.
